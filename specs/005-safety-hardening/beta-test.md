# 0.2.0-beta 수동 테스트 체크리스트 (P0: A1~A5)

테스트 데이터: `N:\codex-A\FileMoa-testdata` (저장소 밖, 실제 파일 아님)

| 폴더 | 내용 |
|---|---|
| `1-organize` | 문서·이미지·동영상·설치파일 등 섞인 파일, 하위 폴더 `sub\report.pdf`(이름 충돌용) |
| `2-duplicates` | 같은 내용 3개(`a.bin`, `b.bin`, `copy of a.bin`) + 크기만 같은 다른 파일 |
| `3-large` | `big-150mb.bin`(150MB), `mid-5mb.bin`(5MB) |
| `4-empty` | 빈 폴더 `a\b` |

앱 데이터(실행 기록): `%APPDATA%\com.cybereun.filemoa\runs\`

개발 빌드 실행: `npm run tauri dev` (저장소 폴더에서). 이미 실행 중이면 창만 확인.

## 1. 실행 기록과 되돌리기 (A2, A3)
1. `1-organize`를 선택하고 **하위 폴더 포함**을 켠 뒤 분석 → 미리보기 확인.
2. 승인·실행 → 정리 기록 탭에 "N files moved"가 보이는지.
3. `runs\` 폴더에 `<uuid>.json`이 생겼고 `.journal` 파일은 남아 있지 않은지.
4. 앱을 완전히 종료했다가 다시 실행 → 정리 기록이 그대로 남아 있는지.
5. 기록의 **되돌리기** → 미리보기 → 확인 → 파일이 원래 위치로 돌아왔는지.
6. 같은 기록이 "N개 되돌림"으로 표시되는지, 앱을 다시 켜도 유지되는지.

## 2. 이름 충돌 (A4)
1. `1-organize` 정리를 다시 만들어 미리보기까지 진행(아직 실행하지 않음).
2. 탐색기에서 `1-organize\문서\PDF\report.pdf`를 직접 만들어 내용을 "내 파일"로 저장.
3. 앱에서 실행 → `report (1).pdf` 같은 번호 파일이 생기고, 직접 만든 `report.pdf`의 내용이 **그대로**인지.

## 3. 휴지통 (A1)
1. `2-duplicates`에서 중복 검사 → 그룹 1개(3개 파일) 표시.
2. 2개를 선택해 휴지통으로 → 안내 문구에 "2개 이동"이 나오고, 파일이 실제로 휴지통에 있는지.
3. (선택) `Z:`(NAS) 드라이브에 연습용 파일을 하나 만들어 같은 방식으로 시도 → **삭제되지 않고** "이동식 드라이브…" 사유가 표시되는지.
4. (선택) 휴지통 속성에서 해당 드라이브 최대 크기를 아주 작게 설정 → `3-large\big-150mb.bin`을 휴지통으로 → Windows의 "영구 삭제" 경고가 뜨는지, 취소하면 파일이 남는지. **경고 없이 바로 사라지면 즉시 알려줄 것.** 확인 후 휴지통 크기 설정을 원래대로 되돌릴 것.

## 4. 클라우드 전용 파일 (A5)
1. OneDrive 폴더에서 파일 몇 개를 "공간 확보"로 온라인 전용으로 바꾼다.
2. 그 폴더에서 중복 검사·대용량 검사 → "클라우드 전용 파일 N개는 … 제외" 안내가 뜨고, 파일이 **다운로드되지 않는지**(아이콘이 구름 상태 유지).

## 5. 기존 기록 이전 (A2)
- 이전 버전(0.1.6)을 쓰던 PC라면: 첫 실행 후 예전 정리 기록이 목록에 보이는지.
