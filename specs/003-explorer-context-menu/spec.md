# Feature Specification: Windows 셸 컨텍스트 메뉴 실행

**Feature Branch**: `003-explorer-context-menu`

**Created**: 2026-09-13

**Status**: Complete

**Input**: User description: "탐색기 특정 폴더, 바탕화면 등에서 마우스 오른쪽 창에 앱 목록이 뜨도록해줘. 거기서 실행하도록 해줘"

## User Scenarios & Testing

### User Story 1 - 폴더에서 바로 정리 시작 (Priority: P1)

사용자는 Windows 탐색기에서 특정 폴더를 오른쪽 클릭하고 FileMoa를 선택해, 폴더를 다시 찾거나 경로를 복사하지 않고 정리 화면을 시작한다.

**Why this priority**: 반복적인 폴더 선택을 줄이고 FileMoa의 핵심 흐름으로 가장 빠르게 진입하게 한다.

**Independent Test**: 설치된 앱에서 임시 폴더를 오른쪽 클릭하고 FileMoa를 선택했을 때 앱이 열리고 그 폴더가 선택된 상태인지 확인한다.

**Acceptance Scenarios**:

1. **Given** FileMoa가 설치되어 있고 탐색기에 유효한 폴더가 보일 때, **When** 사용자가 폴더를 오른쪽 클릭하고 FileMoa 실행 항목을 누르면, **Then** FileMoa가 열리고 해당 폴더가 정리 대상에 표시된다.
2. **Given** 선택한 폴더가 보호된 시스템 폴더일 때, **When** 사용자가 FileMoa 실행 항목을 누르면, **Then** 앱은 열리지만 정리 미리보기 단계에서 보호 사유를 보여주고 파일을 변경하지 않는다.

### User Story 2 - 바탕화면과 폴더 배경에서 실행 (Priority: P1)

사용자는 바탕화면이나 탐색기 폴더의 빈 공간을 오른쪽 클릭해 현재 위치를 FileMoa에 전달한다.

**Why this priority**: 바탕화면과 다운로드 폴더처럼 자주 정리하는 위치를 한 번의 동작으로 지원한다.

**Independent Test**: 바탕화면 빈 공간과 탐색기 빈 공간에서 실행한 뒤 각각 현재 폴더가 선택되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 바탕화면 빈 공간을 오른쪽 클릭할 때, **When** FileMoa 실행 항목을 누르면, **Then** 바탕화면 경로가 선택된 FileMoa 창이 열린다.
2. **Given** 사용자가 탐색기 폴더의 빈 공간을 오른쪽 클릭할 때, **When** FileMoa 실행 항목을 누르면, **Then** 그 탐색기 폴더가 선택된 FileMoa 창이 열린다.

### User Story 3 - 설치·제거와 안전한 실패 (Priority: P2)

사용자는 별도 관리자 권한 없이 설치 후 셸 메뉴를 사용할 수 있고, 제거 후 FileMoa 메뉴가 남지 않으며, 잘못된 실행 인자는 안전하게 거부된다.

**Why this priority**: 셸 통합은 설치·제거 수명주기와 보안이 맞지 않으면 시스템에 잔여 항목이나 의도하지 않은 실행을 남길 수 있다.

**Independent Test**: 현재 사용자 설치를 완료한 뒤 메뉴를 확인하고, 제거 후 같은 위치에서 메뉴가 사라지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 현재 사용자용 설치를 진행할 때, **When** 설치가 완료되면, **Then** FileMoa 셸 메뉴가 등록되고 관리자 권한을 요구하지 않는다.
2. **Given** FileMoa를 제거할 때, **When** 제거가 완료되면, **Then** FileMoa가 만든 셸 메뉴와 아이콘 연결만 삭제된다.
3. **Given** 셸 메뉴가 유효하지 않거나 존재하지 않는 경로를 전달할 때, **When** FileMoa가 실행되면, **Then** 앱은 안전한 빈 상태 또는 오류 안내로 열리고 파일 변경을 실행하지 않는다.

### Edge Cases

- 경로에 공백·한글·괄호가 포함되어도 정확히 한 경로로 전달되어야 한다.
- 네트워크·클라우드·외장 저장장치 경로는 기존 FileMoa 경고를 표시하고 셸 실행 자체는 허용한다.
- FileMoa 실행 파일이 이동·삭제된 뒤 남은 메뉴는 오류를 표시하며 다른 프로그램을 실행하지 않는다.
- Windows 11의 새 컨텍스트 메뉴에서 직접 보이지 않는 경우 추가 옵션 메뉴에서도 접근 가능해야 한다.
- 이미 FileMoa가 실행 중이어도 새 셸 실행은 전달받은 폴더를 가진 별도 안전한 세션으로 열리거나 명확한 오류를 보여야 한다.

## Requirements

### Functional Requirements

- **FR-001**: 시스템은 폴더 자체, 폴더 배경, 바탕화면 배경, 드라이브 위치의 오른쪽 클릭 메뉴에 FileMoa 실행 항목을 제공해야 한다.
- **FR-002**: 실행 항목은 클릭된 폴더 또는 현재 배경 폴더의 경로를 FileMoa에 전달해야 한다.
- **FR-003**: FileMoa는 셸에서 전달된 경로를 시작 화면의 정리 대상 폴더로 표시해야 한다.
- **FR-004**: 전달 경로가 없거나 폴더가 아니면 FileMoa는 파일을 변경하지 않고 사용자가 이해할 수 있는 오류를 표시해야 한다.
- **FR-005**: 셸 등록은 현재 사용자 범위로 제한하고 관리자 권한을 요구하지 않아야 한다.
- **FR-006**: 제거 과정은 FileMoa가 만든 셸 등록 항목만 삭제해야 한다.
- **FR-007**: 경로 인자는 공백·유니코드·특수문자를 포함해도 명령 주입 없이 단일 경로로 처리되어야 한다.
- **FR-008**: 보호된 시스템·개발 프로젝트 경로는 기존 FileMoa 보호 정책을 동일하게 적용해야 한다.
- **FR-009**: 설치 파일과 업데이트로 실행 파일 위치가 바뀌어도 셸 항목은 현재 설치 위치를 가리켜야 한다.
- **FR-010**: 셸 메뉴 라벨과 오류 안내는 한국어·영어 UI 전환 정책과 충돌하지 않는 중립적 표기를 제공해야 한다.

### Key Entities

- **ShellMenuRegistration**: 등록 대상(폴더, 배경, 드라이브), 표시 이름, 실행 파일 경로, 경로 인자 방식, 설치·제거 상태.
- **ShellLaunchRequest**: 셸에서 전달된 원본 경로와 유효성 결과. 파일 이동 권한이나 정리 승인 자체를 포함하지 않는다.

## Success Criteria

### Measurable Outcomes

- **SC-001**: 설치가 끝난 뒤 4개 대상(폴더, 폴더 배경, 바탕화면 배경, 드라이브)에서 FileMoa 메뉴가 각각 1회 클릭으로 실행된다.
- **SC-002**: 공백·한글이 포함된 경로 20건의 테스트에서 100% 올바른 폴더가 시작 화면에 표시된다.
- **SC-003**: 셸 실행 직후에는 파일 이동이 0건이며, 기존 미리보기·승인 절차를 거친 경우에만 이동이 가능하다.
- **SC-004**: 제거 후 4개 대상의 FileMoa 메뉴가 100% 제거되고 다른 셸 메뉴는 변경되지 않는다.
- **SC-005**: 잘못된 경로·보호 경로 테스트 10건에서 파일 변경이나 영구 삭제가 0건이다.

## Assumptions

- Windows 10/11 x64·ARM64의 현재 사용자용 NSIS 설치를 기본 대상으로 한다.
- 셸 통합은 기본 활성화하고, Windows 11에서는 레거시/추가 옵션 메뉴에 나타날 수 있음을 안내한다.
- 한 번의 셸 실행은 하나의 폴더 경로만 전달한다. 여러 폴더 선택은 FileMoa 내부 기능을 사용한다.
- 셸 통합은 FileMoa 실행 경로를 설치 시점에 기록하며, 업데이트는 같은 설치 경로를 유지한다.
- 파일 내용·경로·사용자 행동을 외부 서비스로 전송하지 않는다.
