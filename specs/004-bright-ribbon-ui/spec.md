# Feature Specification: Bright Ribbon Workspace

**Feature Branch**: `004-bright-ribbon-ui`

**Created**: 2026-09-13

**Status**: Draft

**Input**: User description: "빠른 폴더 메뉴를 가로로 보기 좋게 정렬하고 이미지 2를 참고한 밝은 모드 색상으로 전체 앱을 개선한다."

## User Scenarios & Testing

### User Story 1 - 빠른 폴더를 한눈에 선택하기 (Priority: P1)

정리 화면에서 사용자는 자주 사용하는 폴더를 세로로 눌린 버튼을 해석하지 않고, 읽기 쉬운 가로형 목록에서 바로 선택한다. 폴더가 많아도 각 버튼의 이름과 아이콘이 잘리지 않아야 한다.

**Why this priority**: 빠른 폴더는 파일 정리의 첫 단계인 대상 폴더 선택을 빠르게 만드는 핵심 경로이며, 현재 레이아웃의 가장 큰 사용성 문제다.

**Independent Test**: 데스크톱 창에서 정리 탭을 열고 등록된 빠른 폴더를 확인한 뒤 임의의 폴더 버튼을 클릭한다. 버튼이 가로로 읽히고 선택된 경로가 유지되면 이 이야기의 가치를 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 등록된 빠른 폴더가 둘 이상일 때, **When** 정리 탭을 연다, **Then** 빠른 폴더 버튼이 가로 행에 표시되고 글자가 세로로 눌리지 않는다.
2. **Given** 빠른 폴더 행이 창 너비보다 길 때, **When** 사용자가 행을 살펴본다, **Then** 버튼이 서로 겹치지 않고 가로 스크롤 또는 자연스러운 줄바꿈으로 모든 폴더에 접근할 수 있다.
3. **Given** 빠른 폴더 버튼을 클릭했을 때, **When** 대상 폴더가 선택된다, **Then** 기존 미리보기·실행 흐름과 동일하게 선택 경로가 갱신된다.

### User Story 2 - 밝고 편안한 작업 화면 사용하기 (Priority: P1)

사용자는 이미지 2의 따뜻한 아이보리·웜 그레이·테라코타 조합을 바탕으로 정리, 관리, 안전, 설정 및 업데이트 화면을 밝은 모드에서 사용한다. 텍스트, 입력창, 상태 배지, 주요 동작 버튼은 배경과 명확히 구분된다.

**Why this priority**: 장시간 파일을 검토하는 작업에서는 가독성과 시각적 일관성이 신뢰감과 실수를 줄이는 데 직접적인 영향을 준다.

**Independent Test**: 각 탭과 설정/업데이트 팝업을 순서대로 열어 배경, 카드, 버튼, 입력창, 상태 메시지를 확인한다. 모든 화면에서 한국어와 영어 텍스트를 읽을 수 있고 대비가 유지되면 독립적으로 통과한다.

**Acceptance Scenarios**:

1. **Given** 앱을 실행했을 때, **When** 기본 화면을 확인한다, **Then** 전체 배경은 밝은 아이보리 계열이고 콘텐츠 표면은 흰색/웜 그레이로 구분된다.
2. **Given** 리본의 동작 버튼이나 설정 항목을 볼 때, **When** 마우스를 올리거나 포커스를 이동한다, **Then** 테라코타 계열 강조색과 명확한 포커스 표시가 나타난다.
3. **Given** 계획, 성공, 경고, 오류 상태가 표시될 때, **When** 상태를 읽는다, **Then** 각 상태가 색상뿐 아니라 텍스트/배지로 구분되고 밝은 배경에서도 식별된다.

### User Story 3 - 창 크기와 언어에 관계없이 리본 사용하기 (Priority: P2)

사용자는 한국어·영어를 전환하거나 창 크기를 줄여도 리본의 주요 기능과 현재 경로를 잃지 않는다. 좁은 창에서는 컨트롤이 겹치지 않고 필요한 경우 스크롤할 수 있다.

**Why this priority**: 다양한 화면 크기와 두 언어의 문자열 길이를 안전하게 지원해야 실제 배포 환경에서 동일한 작업 경험을 제공할 수 있다.

**Independent Test**: 한국어와 영어에서 약 940px 및 520px 너비로 창을 조정하고 정리/관리/안전 탭을 확인한다. 버튼·셀렉트·경로가 잘리지 않고 키보드 포커스로 접근 가능하면 통과한다.

**Acceptance Scenarios**:

1. **Given** 영어로 전환한 상태에서, **When** 좁은 창을 사용한다, **Then** 긴 레이블이 다른 컨트롤을 밀어내거나 겹치지 않는다.
2. **Given** 창 너비가 줄어들었을 때, **When** 리본을 탐색한다, **Then** 주요 동작과 빠른 폴더에 스크롤 또는 줄바꿈으로 접근할 수 있다.
3. **Given** 밝은 테마를 적용한 상태에서, **When** 파일 정리·Undo·중복 탐색을 실행한다, **Then** 기존의 미리보기 승인, 보호 경계, 실행 및 되돌리기 동작은 변경되지 않는다.

### Edge Cases

- 등록된 폴더 이름이나 경로가 매우 길거나 유니코드 문자를 포함해도 버튼은 한 줄로 읽히며 전체 경로는 툴팁/경로 표시로 확인할 수 있다.
- 등록된 빠른 폴더가 없으면 빠른 폴더 영역이 불필요한 빈 공간을 만들지 않는다.
- 한국어·영어 레이블 길이가 달라도 리본 컨트롤은 최소 클릭 영역을 유지한다.
- 상태 색상만으로 의미를 전달하지 않고 상태 텍스트와 아이콘을 함께 제공한다.
- Windows 고대비 설정이나 키보드 포커스에서도 테두리와 포커스 링이 보인다.

## Requirements

### Functional Requirements

- **FR-001**: 정리 탭은 빠른 폴더 항목을 읽을 수 있는 가로형 행으로 표시해야 한다.
- **FR-002**: 빠른 폴더 항목은 서로 겹치거나 세로 문자로 축소되지 않아야 하며, 공간이 부족하면 가로 스크롤로 접근할 수 있어야 한다.
- **FR-003**: 빠른 폴더 항목을 선택하면 기존 폴더 선택·미리보기·파일 이동 흐름을 그대로 사용해야 한다.
- **FR-004**: 앱의 기본 시각 테마는 밝은 아이보리 캔버스, 흰색/웜 그레이 표면, 테라코타 강조색을 사용해야 한다.
- **FR-005**: 정리·관리·안전·설정·업데이트·AI 화면의 텍스트, 입력, 버튼, 상태 및 모달은 밝은 테마에서 읽기 쉬운 대비를 제공해야 한다.
- **FR-006**: 한국어와 영어 전환 시 모든 리본 레이블과 빠른 폴더 영역은 잘림·겹침 없이 표시되어야 한다.
- **FR-007**: 데스크톱 창 너비 변화에 따라 리본 동작, 옵션, 빠른 폴더, 현재 경로를 스크롤 또는 줄바꿈으로 계속 접근할 수 있어야 한다.
- **FR-008**: 본 변경은 파일 분류 규칙, 미리보기 승인, 보호 경계, 파일 이동, Undo, 중복 탐색 및 기록의 동작을 변경하지 않아야 한다.
- **FR-009**: 모든 상호작용 가능한 리본 요소는 마우스·키보드 포커스·비활성 상태를 시각적으로 구분해야 한다.

### Key Entities

- **RibbonLayout**: 동작 버튼, 정리 옵션, 빠른 폴더, 현재 경로를 사용자가 탐색하는 시각적 영역.
- **ThemePalette**: 캔버스, 표면, 선, 본문, 보조 텍스트, 강조색 및 상태색의 의미 있는 색상 집합.
- **QuickFolderItem**: 저장된 폴더 식별자, 표시 이름, 실제 경로 및 폴더 선택 동작을 가진 빠른 접근 항목.

## Success Criteria

### Measurable Outcomes

- **SC-001**: 1280px 이상 창에서 등록된 빠른 폴더 6개와 리본 주요 동작 버튼이 세로 축소·겹침 없이 한눈에 읽힌다.
- **SC-002**: 760px 이상 창에서 각 빠른 폴더 항목을 한 번의 클릭으로 선택할 수 있고 선택 경로가 즉시 표시된다.
- **SC-003**: 정리·관리·안전·설정·업데이트 화면에서 본문과 컨트롤이 밝은 배경과 구분되며 기존 자동화 테스트와 프런트엔드 빌드가 통과한다.
- **SC-004**: 한국어와 영어, 940px 및 520px 창 너비 조합에서 주요 리본 기능과 현재 경로가 숨겨지지 않는다.
- **SC-005**: 테마와 레이아웃 검증 중 파일 시스템에 파일 이동·삭제·이름 변경 작업이 0건 발생한다.

## Assumptions

- 밝은 테마를 기본값으로 제공하며 이번 범위에서는 별도의 다크 모드 전환 설정을 추가하지 않는다.
- 이미지 2의 따뜻한 색감은 참고하되, 텍스트와 상태 표시의 접근성을 우선한다.
- 기존 React/Lucide 구성과 폴더 선택 로직을 재사용하고 새로운 런타임 의존성은 추가하지 않는다.
- 이번 변경 범위는 시각적 레이아웃과 테마이며, 파일 정리 도메인 규칙과 안전 장치는 기존 구현을 유지한다.
- Windows 데스크톱 창을 주요 대상 범위로 하며 모바일 전용 레이아웃은 범위 밖이다.
